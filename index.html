Welcome everyone. Today I'm excited to introduce OpenClaw - a revolutionary open-source AI assistant framework. This is a technical talk for developers, so we'll dive into architecture, security, and implementation details.

The Problem

  • Current AI assistants are cloud-dependent
    • Privacy concerns with your data
    • Vendor lock-in
  • Limited control over infrastructure and data
  • Fragmented communication
    • AI only works in specific apps
    • No unified assistant across platforms
  • 🔒 Trust boundaries outside your control
The AI assistant landscape has a fundamental problem. Whether you're using ChatGPT, Google Assistant, or others, they all require sending your data to the cloud. You have no control over where it goes, how it's processed, or who has access. And they're siloed - your assistant in one app doesn't work in another.

What is OpenClaw?

  • Personal AI assistant that runs on YOUR hardware
  • Multi-channel messaging integration
    • WhatsApp, Telegram, Slack, Discord, and more
  • Originally "Clawdbot" by Peter Steinberger (Nov 2025)
  • Renamed to OpenClaw (Jan 2026) after trademark issues
  • 📈 Explosive growth: 9k → 60k+ GitHub stars in days
OpenClaw is your personal AI assistant that runs entirely on your own infrastructure. It started as Clawdbot, a personal project, and went viral. After some trademark drama with Anthropic, it was renamed to OpenClaw and the growth has been astronomical - one of the fastest-growing open source projects in history.

Core Architecture

WebSocket Gateway Control Plane

ws://127.0.0.1:18789

  • 🤖 Pi agent runtime in RPC mode
  • 📬 Multi-channel inbox connectivity
  • 🔧 Tool execution framework
  • 🔌 Model-agnostic LLM integration
At the heart of OpenClaw is a WebSocket-based gateway that acts as the control plane. It uses Pi agent runtime to connect to various LLM providers, manage multi-channel messaging, and execute tools on your behalf. Everything communicates through this central gateway.

Here's the full stack. Users interact through any messaging platform. The gateway routes messages to the agent runtime, which calls the LLM and executes tools. Everything runs locally on your machine.

The skill system is incredibly powerful. Out of the box, you get over 100 skills that can control your browser, run shell commands, manage files, and more. It can even generate visual interfaces on the fly using the A2UI canvas system.

Model Support & Flexibility

  • Model agnostic - works with any LLM API
  • 🌟 Recommended: Anthropic Claude Pro/Max
    • Claude Opus 4.6 (latest and most capable)
  • Also supports:
    • KIMI K2.5
    • Xiaomi MiMo-V2-Flash
    • Any OpenAI-compatible API
  • Why Claude?
    • Long-context strength (200k+ tokens)
    • Prompt-injection resistance
You're not locked into a single AI provider. OpenClaw works with any LLM, though Claude is recommended because of its strong context handling and better security against prompt injection. But you can use whatever model fits your needs and budget.

Security & Privacy 🔒

  • Local-first philosophy
    • "Your infrastructure. Your keys. Your data."
  • Default: tools execute on host for personal sessions
  • Optional: Docker sandboxing for group/channel sessions
  • Recent security hardening
    • 34 security commits in recent updates
  • ⚠️ Acknowledged challenge: prompt injection
    • Industry-wide unsolved problem
    • Be cautious with exposed instances
Security is taken seriously. The core principle is local-first - your data never leaves your control unless you explicitly send it to an LLM API. For group chats, you can use Docker sandboxing. That said, prompt injection remains an unsolved problem across the entire AI industry. Don't expose your instance to untrusted users without understanding the risks.

Installation & Getting Started


# Install OpenClaw globally
npm install -g openclaw@latest

# Run onboarding and install daemon
openclaw onboard --install-daemon
  • Requires Node.js ≥22
  • Update channels: stable / beta / dev
  • Quick onboarding process guides you through setup
Getting started is incredibly simple. Two commands and you're up and running. The onboarding process walks you through connecting your messaging platforms and configuring your LLM API keys. The whole setup takes less than 10 minutes.
